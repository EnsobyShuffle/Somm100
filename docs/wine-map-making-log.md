# SOMM100 Wine Maps · 制作工作日志与地图模板

> 状态：工作中的地图制作规范；每完成一个产区，补记数据、交互和验收结果。  
> 当前样板：Champagne（第一版）  
> 记录开始：2026-10-29

## 目标

把地图做成 SOMM100 内可直接使用的地理学习工具：沿着真实地理底图定位产区，再叠加有来源的葡萄酒知识图层。用户可以拖动、缩放、点选地图要素，并从地图进入对应知识资料。

## 先统一术语

| 图层 | 表示什么 | 能否互相替代 |
|---|---|---|
| 地理底图 | 城镇、道路、河流、地形等地理背景 | 不能代替葡萄酒产区资料 |
| 法定地理范围 | AOC/AOP 或其他产区的法定范围 | 不等于实际栽植葡萄的地块 |
| 法定地籍/地块界线 | 地籍图中的土地边界，或 INAO 公布的法定原料产区边界 | 普通地籍地块不自动具备葡萄园、AOC 或酒庄归属含义 |
| 葡萄园/栽植范围 | 真实葡萄种植位置或地块 | 必须有可核实来源，不能由地籍边界推断 |
| 教学标注 | 城镇、葡萄品种、坡向、酒庄、酒款、历史信息 | 每项需标明是事实点、概略范围还是示意 |

## 可复用制作框架

1. **先确定尺度与学习问题**：国家、产区、村庄或地块；先写清楚用户在该尺度上要看懂什么。
2. **选可交互地理底图**：支持移动、缩放、触屏；底图只负责地理背景，地图服务可替换。
3. **分开准备专题数据**：分别维护行政/法定边界、村庄/地标、葡萄园、地籍、分级与酒庄等 GeoJSON 图层。
4. **给每个要素留证据**：名称、类型、来源 URL、来源日期、几何状态（官方/核实/概略）、授权、版本、关联 SOMM100 知识 ID。
5. **按层级呈现**：远景显示主要产区与河流/城市；中景显示村庄与分区；近景才加载细小地籍或葡萄园要素，避免小地块在全区图上挤成一片。
6. **每个图形可解释**：点击后显示其身份、地理/法定状态、来源与相关 Wine Library 内容；没有资料时明确写待补，不生成虚构地块信息。
7. **手机先验收**：窄屏可拖动、双指缩放、点按命中、卡片可关闭/返回；同时核对 390px 布局、触屏手势和地图图层加载。

## 当前技术模板

- SOMM100 内部路由和知识关联继续沿用现有 App，不把地图作为另一个独立产品交付。
- 地图引擎、底图和酒类专题数据分离；专题数据采用可版本化的 GeoJSON/结构化记录。
- 当前项目未配置 Google Maps API Key，因此 Champagne 首版采用无需个人密钥的 OpenStreetMap 地理底图并标注版权；底图适配层保留将来接 Google Maps 的入口。只有在获得并配置合法 API Key 后，才能切换到 Google Maps 作为底图。
- 地图几何从 GeoJSON/地理坐标渲染；样式和交互不能改变其数据来源或法律含义。
- 网络底图不可用时明确显示加载状态/归属信息；外部底图请求失败不应把示意图冒充真实地图。

## 第一版数据质量分级

- **A｜官方几何**：发布方、发布日期和许可可查；可展示原始来源与版本。
- **B｜来源核验的事实点**：有官方/可靠来源坐标，但点位只作为城镇或地标定位。
- **C｜概略范围**：由权威资料描述的区域，用于教学定向，注明不是法定边界。
- **D｜示意几何**：仅作为界面草图；不可标作真实地块、法定边界或葡萄园。

任何图层都必须在地图图例与点选卡片中显示等级；A 级可称“官方几何”，C/D 级不得用实线制造法定边界的视觉暗示。

## 研究摘录

- **Wine Scholar Guild**：参考其按国家/产区组织教学主题与专题图的方式；地图要服务课程学习，不把地图本身当作唯一内容。
- **De Long Wine Maps**：参考其地图编辑、地形关系和产区内容编排；视觉地图与可交互底图是不同交付形态，不直接把静态图当作手机地图产品。
- **原创与商用原则**：WSG 与 De Long 只作为质量和信息组织参照。不得复刻它们的地图构图、图例、配色组合、字体/标注样式、插图、文案、数据编排或受版权保护的地块绘图。每个 Wine Maps 产区采用 SOMM100 自己的组件、符号、色彩和说明语气；地理数据按各自开放许可或取得的使用授权单独核验。通过模仿无法自动取得商用权利。
- **Wine Maps（iOS）**：作为手机端找产区、找地点的交互参考；要把搜索、定位、缩放、点位说明做成直观操作。
- **Google Maps**：参考基础地图画布、连续缩放、拖动、道路地名和多图层交互模式；专题葡萄酒信息由 SOMM100 自己提供。当前项目没有 Google Maps API Key，因此首版实际使用 OSM 瓦片，后续可替换底图适配器。
- **Champagne Atlas（wineatlas.app/champagne）**：目前最贴近“通用地图底图 + 葡萄酒专题细层”的交互样板。其公开说明展示按缩放级别打开 IGN vineyard land、地籍 lieux-dits、地籍地块和航片推算行向等图层，并给每层写明来源和局限。只借鉴图层架构、尺度切换和来源说明，不复制其代码、视觉或未经授权的数据。
- **Champagne 数据结论**：INAO 的公开法定葡萄园分界数据并非完整数字化，资料也明确不是具法律效力的唯一边界图；INAO 的正式边界计划另有官方门户。Champagne Atlas 说明其 vineyard footprint 来自 IGN BD TOPO（nature=Vigne），地籍地块、lieux-dits 与法定 AOC 资格分别处理。因而“葡萄园地表范围”可先用可授权的 IGN 数据做独立图层；“AOC 法定资格”不得从一般葡萄园或地籍几何推断。
- **统一模板结论**：通用地图画布/底图 + 按比例尺加载的葡萄酒专题叠加层 + 可追溯的点击卡片。图层至少拆为行政/产区、法定范围、葡萄园覆盖、地籍地块/lieux-dits、酒庄/酒款和教学注释；每层单独记录来源、许可、时间、几何精度和不可推断事项。
- **当前 Champagne 实际范围**：v0.4.5 已上线的是 OSM 地理底图、18 个精选村镇定位和四个主要种植区教学标签。它是地图交互框架首版，不是葡萄园地块地图；还没有 IGN vineyard polygons、cadastre 地籍细层或航片行列层。记录这个差距，避免把首版宣传为完成品。

### 2026-10-29 · Champagne 地图按真实葡萄园专题层重做

- **触发原因**：用户审阅上一版后指出，它虽有漂亮的配色，却没有达到专业葡萄酒地图应有的地理信息与细节密度。该版本不得再作为“完成的 Wine Map”交付。
- **参照标准**：WSG 与 De Long 仅用于校准地图需要的产区层级、地理关系、图例解释与可读性。禁止沿用其独有构图、图形、符号系统、文本或数据绘制。SOMM100 使用现有品牌的深绿、橄榄、暖白与金色点缀，并重新设计图层交互和信息卡。
- **实际地理数据**：以 OpenStreetMap 连续地理底图作为画布；接入法国 IGN `BDTOPO_V3:zone_de_vegetation` WFS，仅取 `nature=Vigne` 的葡萄园面几何。请求按视窗范围与缩放级别分段加载，远景不展示未达到可辨识尺度的小面；地图放大后显示真实多边形覆盖，可点选单个几何。
- **点击记录**：IGN BD TOPO 的每条葡萄园要素卡片显示 `cleabs` 稳定记录号、`precision_planimetrique` 平面位置精度、`methode_d_acquisition_planimetrique` 采集方式与记录日期，并链接 IGN 与 INAO 数据说明。
- **地块含义边界**：IGN `Vigne` 几何表示地形数据库所记录的葡萄园覆盖。它不是单块葡萄行、不是地籍权属线，也不构成 INAO 法定 AOC 界线或资格证据。地图图例、选中卡片和正文读图说明重复此边界，避免把不同空间数据混为一谈。几何精度按数据条目显示，不对其精度作统一承诺。
- **村镇图层**：扩展到香槟核心村镇和官方 17 个 Grand Cru 村庄。可匹配现行 IGN commune 几何的点以 commune 质心作定位参考；已合并的历史村名仍使用近似定位并标明非地块几何。点位不宣称精确到葡萄园或村内 AOC parcel。地图名称标签延后到村镇尺度，减少远景拥挤。
- **手机交互**：沿用现有触屏地图画布的单指拖动、双指缩放、缩放按钮与轻触选取；增加 vineyard 面的触屏点选。小屏上图层说明与选取卡片保持可用，载入状态随当前地图视野更新。
- **开放数据和许可记录**：OSM attribution 保留在地图底部；IGN BD TOPO 页面标明 Licence Ouverte 2.0。WSG、De Long 作品只作产品标准对标，不用它们的图像或数据。
